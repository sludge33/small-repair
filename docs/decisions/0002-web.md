# 0002 – Build for the web, not Unity

**Status:** Accepted, 2026-11-04. Replaces [0001](0001-engine.md).

## Decision

Build the kintsugi bowl prototype as a **mobile web game (TypeScript, Vite, Web Audio, installable PWA on GitHub Pages)**, the same way as True Hoof and Underbrush. Keep a native wrapper (Capacitor) as the route to rich haptics and the app stores.

## Why

- **Every push reaches a phone.** Playtesters open a URL or add it to the home screen. No device builds, no Mac for an iPhone test, no Unity licence limits.
- **FMOD is not needed for the slice.** Web Audio covers what the gesture model drives: looping layers, equal-power crossfades, pitch, low-pass, pan and per-frame parameters.
- **The rules stay separate and tested.** The gesture analyzer, modulation mapper and tick stream are pure TypeScript with no browser dependencies, as Underbrush's core is.

## Trade-offs accepted

- **No haptics on iPhone in the browser.** WebKit has never shipped the Vibration API. The hidden-switch workaround gives a single fixed tick at best and is reported to be patched in iOS 26.5. Until a native build exists, iPhone players get sound and visuals only, which falls short of the pillar that a muted device still feels every stroke.
- **Coarse haptics on Android.** Chrome's Vibration API has on/off and duration only, with no amplitude or sharpness, so per-material textures cannot be fully expressed. Firefox has removed it.
- **Playtest results need splitting by platform.** The go/no-go criteria include feel, so judge haptics only from players on a device that has them.
- **No middleware tooling.** A sound designer tunes in code or through exposed parameters rather than in FMOD Studio.

## Not yet decided

- **When to delete `prototype/`.** It stays until the web build has been checked on a phone.

## Objects are 3D

The object being repaired is 3D, rendered with Three.js (WebGL), with paint masks held on the CPU and uploaded as textures. Orbiting to inspect, fitting shards into the bowl and strokes that follow a curved surface are core to the game. The shop, letters and UI stay flat 2D, as the design doc already specifies. The placeholder bowl can be generated in code, so the prototype still needs no art pipeline.

## Paint masks are on the CPU

The design doc plans GPU render textures. The masks are CPU `PaintMask`s instead: reading coverage back from the GPU stalls a phone, while a stamp on the CPU touches a few hundred bytes and keeps an exact, testable running count. Each frame uploads only the block of texels a stroke changed, rather than the full 1024×512 mask.

## Keeping the frame rate on a phone

- **Fingers pick through a spatial index (`three-mesh-bvh`).** Testing all 41,000 of the bowl's triangles took 4.3 ms per touch frame on a desktop, so several times that on a phone. The index took it to 0.23 ms with exact hits. A coarser pick mesh was tried first and rejected: 2.4 times faster, and up to about 2 mm off.
- **The bowl is drawn only when something on it changed.** The shadow map is redrawn only when the bowl moves, since paint casts no shadow.
- **Resolution steps down on a phone that cannot keep up** (`ResolutionGovernor`): under 28 frames per second over 90 drawn frames lowers the pixel ratio a step, from 2 towards 1. It never steps back up, which would flicker. The threshold sits under 30 so that a low-power mode's frame cap does not cost sharpness for nothing, and it is not yet tuned on a device.

## Follow-ups

- Check on phones: which touch signal each one reports (`Touch.radiusX` or `Touch.force`; the overlay shows it), whether fast `navigator.vibrate` ticks read as a texture, audio latency, and what the overlay's frame figures say.
- Grain jitter from the spec is still not implemented, only the low-pass, as in the Unity version.
